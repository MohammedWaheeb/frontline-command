# Genuine browser offline-upgrade acceptance plan

29 September 2026. **Prepared only; no browser/host run.** Applies to packaging checkpoint `a53fda9` and a newly built product such as v25 that actually includes its worker/installer. Frozen v23/v24 use old pack identity and must remain unchanged. Fake CacheStorage tests are unit evidence, not these gates.

Use two separately frozen future build directories with the same stable pack ID and different derived versions. Both must pass the exact package audit. Serve at one localhost origin with a controllable test-only file server; do not change the production cache algorithm. Record browser executable/version, secure context, `navigator.locks` presence, worker script hash, both pack/index hashes, completed marker/cache names and ordinary App install status. Never log credentials/profile requests.

1. **Cold old install:** Install A through App controls; verify actual index/WASM/audio/art responses. Close the document/browser normally, stop the host, relaunch the same origin with network disabled and verify the cached shell plus real solo Go start/save. This is distinct from a warm tab remaining open.
2. **Unchanged reuse:** Reopen App, select A again and count actual file requests. No file downloads, cache duplication or change of selected generation is expected.
3. **Successful upgrade:** Bring host online with B. Require index→manifest identity agreement and changed derived version. Install B through App. Then cold offline reload must boot B and start its real runtime. An A-only path must return503, never resurrect from A. Retired A stays available, not mixed into B.
4. **Failure before commit:** On fresh profiles, interrupt, abort, truncate, corrupt equal-length file bytes, and exhaust storage during B. Preserve the failed staging/cache cleanup diagnostics. Offline A must remain usable, B must have no READY marker, and a retry must succeed. Test abort before calling install separately: it must not reactivate an old completed cache.
5. **Two-tab lock ordering:** Keep A installed. In tab1 start B and hold a real file response before verification completes; tab2 installs C to completion. Release B and verify B's marker is activated after C using a fresh completed-generation read. Repeat with tab2 explicitly reactivating a cached older generation while B is downloading. Use an independent tab's CacheStorage read and actual offline worker response to prove the winner. Request a real Web Lock in the diagnostic tab to temporarily hold only activation, cancel the waiting installer, and verify no unexpected marker/rollback. Never infer cross-tab correctness merely from one App's task serialization.
6. **Legacy same-ms tie:** Prepare two exact verified old completed caches with equal legacy timestamps in a separate diagnostic profile, then verify deterministic cache-name selection in the new worker and installer. Explicitly choosing the nonselected completed version must advance its activation. This is disclosed cache-metadata preparation, not a gameplay fixture. Real concurrent tests should not freeze wall clocks globally.
7. **Worker update boundary:** Begin under the genuine previous worker, update to the new worker online and record controllerchange/script identity. Only claim corrected offline fallback once the new worker controls the document. Include an old tab kept open, a navigation after update and a cold launch. Network-first success while connected does not establish offline generation coherence.
8. **No-Web-Locks browser:** Record the actual absence if encountered; test same-context serialization and whole-generation deterministic ties. Cross-tab atomic completion is deliberately **not promised** there. Do not disable Web Locks in a supported browser and call that a stock-browser capability result.
9. **Storage and privacy:** Measure quota failure/retry and manual retired-cache deletion using the established remove operation. Confirm remaining completed generation still works. Verify authenticated/private API requests and multiplayer/profile/save data never enter pack caches. Keep manual cleanup diagnostics separate from a user-facing cleanup UI claim (currently unverified).

Archive failed leaves and request/response timing without tokens. A release result must name the exact product, true browser and worker; no localhost result establishes insecure remote-LAN offline support. This plan changes no global Safari preferences, browser policy, networking permissions or production source.
