## Original consumption and independent raw gate

The observer is installed by CDP **before navigation** because the loader captures
its fetch function at boot. Six established native-reader/CDP/hash helpers are
frozen byte-for-byte from the previous diagnostic. A new adapter supplies these
hard limits:

| Limit | Bound |
| --- | --- |
| Per original body | 8MiB |
| Total incremental bytes per document | 768MiB |
| Simultaneously active hashes | 16 (9,728 bytes of hash arrays) |
| Native request records | 16,384 |
| CDP requests/scripts/record map | 32,768 |
| Optional returned-Blob proof | 8MiB each /16MiB retained |

No original response chunks are retained. Fetch is invoked once with its
original arguments; original reader results and errors pass through. There is
no clone, tee, extra network/body read, timeout override, request interception,
retry or server patch. An optional native returned Blob can be hashed locally
and asynchronously by the existing helper; that consumer is named separately
from original explicit-reader EOF. V3 assets ordinarily use the explicit-reader
path. The instrumentation adds CPU/microtask work, so it is not performance or
deadline-cause evidence.

Expected bytes are selected from the exact manifest **before launch**, plus the
pinned manifest file itself. Every proof needs actual target/native request ID,
default execution context and unique context ID, frame/document, debugger-labelled
observer, full static URL/method and one-to-one serial ordinals. Same-URL overlap,
redirects, service-worker responses, incomplete capture, missing EOF, wrong hash
or count, and trace/budget overflow cannot become exact-body facts. API query
credentials are removed; no headers or authentication tokens are stored.

Native JSON/text, browser Image/SVG/CSS/font consumers and unmatched realms are
listed as unproved. Advice responses have no independent server-body oracle in
this unchanged-host course, so their observed completion is **not** promoted to
an exact expected-body proof. CacheStorage reads and later Blob URL decodes are
not substituted for native HTTP request identity.

`rawDiagnosticStatus` remains independent: **every** unexpected CDP/PW request
failure, page/console/HTTP error, observer fault or count disagreement fails it.
`exactBodyFailureFacts` can only add the observed original byte count/SHA/EOF and
cancellation ordering to that same uniquely identified request. They cannot make
an abort harmless or explain its cause, prove decoding, or turn the raw status
into a pass. The final status requires the bounded functional course, clean raw
diagnostics, complete identified supported static-reader observations, zero
active hashes and retained Blob/chunk bytes, input guards and clean host close. Unsupported
consumer classes remain explicitly outside that proof.

Tests pin wrong expected bytes, missing EOF/realm/context/unique ID, service
worker/overlap denial, unsupported native JSON, incomplete capture/overflow,
CDP/PW disagreement, preserved original fetch/reader identities and strict
failure despite exact same-run bytes. They are helper unit tests, not fabricated
browser or game evidence. Earlier strict failures, including the posthoc initial-A
body proof, remain unchanged.
