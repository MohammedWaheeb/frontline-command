# Staged art to ordinary build: bounded read-only review

The reviewed normalized overlay is suitable for private assembly, but is not a live publisher. The minimum addition is a receipt-bound publication wrapper that stages the accepted exports into the existing `assets/build` layout, validates the actual production plugin's derived inventory, preserves the previous tree, and then runs ordinary `make build`. No new rendering, plugin path convention or manual pack version is needed. This report implements and publishes nothing; exact source/receipt hashes are in `result.json`.

## Concrete current boundaries

Catalog59 seals 59 handoffs, 3,399 files, 654,617,336 bytes and 18,961 poses. Its historical reference union includes 48 inherited IDs, giving 107 of the exact 162 expected IDs (136 resolved catalog IDs plus 26 props). The 55 missing IDs match the remaining 2 aircraft, 21 vehicles and 32 buildings. This is inventory evidence, not acceptance of a final current-client product. The inherited 48 retain their separate lineage limits; presence does not become fresh visual acceptance.

Current53 normalization binds 212 masks to 53 exact handoff identities. Six later selected roles and all future handoffs are outside it. The helper correctly leaves such extra roles unmodified and reports its limited scope. A complete normalized publication needs a new reviewed receipt covering its declared final normalization scope; it must not call the current53 receipt a final one or reuse its US rifle derivative against another handoff. The full normalized copy/pack branch remains unrun.

## What the adapter already guarantees

`overlay-normalized-v1.mjs` checks pinned production/integrity/UI/native receipts, owned per-ID destinations and exact sidecar → atlas JSON → PNG closure. It removes an old selected sprite directory only in the new private clone before copying its replacement, then applies normalization after all copies. The helper checks selected handoff path and SHA, original mask and paired beauty, derivative bytes, four masks per reviewed role, and rejects a changed prepared plan. Final copied world/beauty/UI files are checked, including original-versus-derived mask identities. The pack and generated content-index version are derived after final bytes are in place. Unrelated previous pack entries must remain exact.

These checks do not constitute final selection approval: supplied handoffs can carry internally valid receipts without being members of a separately pinned final roster. The adapter does not globally rehash every entry of `sourceHashes` after copying. Editable `.blend` bytes are hashed for its output receipt but are not compared to a predeclared handoff digest there. Preserve these limits; a publisher must not describe them as existing global pre/post source protection.

## Minimum changes before publication

1. **Bind one selected generation.** Supply a pinned manifest listing each exact expected ID and either its approved handoff path/SHA or its explicitly accepted inherited closure. Bind review/production receipts and source provenance there, including an editable-source digest where claimed. Reject duplicate IDs/roles, stale superseded handoffs, incomplete or unreviewed selections, and extra IDs. Do not choose by directory recency or accept a merely self-consistent handoff as the final selection.

2. **Target the ordinary asset layout.** The existing private CLI assumes `work/art/<base>/{product,build.json,frontline}` and therefore cannot directly publish to `assets/build` or consume a normal `package/client` base. A new wrapper can reuse its validation and normalization code with explicit staging-root mapping: `art/sprites/...` and `art/ui/...` become `assets/build/sprites/...` and `assets/build/ui/...`. Keep the accepted overlay unchanged. Its universal eight-UI-files contract applies to current unit/building handoffs, not the 26 inherited props, which intentionally have no UI. Retain the verified prop closures without inventing portraits. Buildings with null `role_id` still use their complete building ID as the UI key.

3. **Assemble a new tree, preserving the old one.** Clone a pinned current asset baseline into an unserved sibling staging tree. Replace whole selected sprite directories so stale atlas pages cannot survive. Replace only owned UI paths; explicitly remove obsolete keys only when the selection proves a role-key migration. Keep original authored exports, all world qualities and all eight authored UI files. Apply reviewed mask derivatives last. Preserve audio, approved FX, terrain, keyart, chrome, icons, fonts and notices unless separately selected. The production plugin already packages only the four runtime 2x UI files per role; no trimming or budget change is required.

4. **Close both physical and advertised inventories.** Compare the staging tree's complete path/size/SHA inventory against the pinned baseline plus exact selected replacement and normalization deltas. Call current `artPackageSources` against that isolated asset root and require exact sprite IDs, portrait/build keys and recursive runtime file closure. `artIndex` intentionally skips malformed/in-progress exports, so a successful build alone does not prove all expected IDs were included. Reject unknown sidecars, duplicate destination aliases, symlink escapes, unowned extra files and missing required 2x pairs. A missing pair must fail the publication check instead of quietly becoming a world-art fallback. Recheck all selected source/receipt and inherited input pins after the copy; this is the new guard required before claiming global input immutability.

5. **Switch under an exclusive publication boundary and build normally.** Stop serving/authoring the affected root, preserve the former `assets/build` under an immutable backup outside the plugin's scanned root, and move the fully checked staging tree into place with a recorded rollback path. Two directory renames are not an atomic pair; keep readers closed until validation finishes and restore the prior tree on failure. Do not delete the old tree or mutate models/raw handoffs. Ordinary `make build` then uses the already integrated packaging input/output guard and current plugin. Verify its `art/index.json` and package paths against the publication receipt and retain the freshly derived pack/content identity. Measure the final complete encoded pack against the unchanged 16,000-file/2GiB limits; the present conservative projection is not a final assembled-pack receipt.

A partial staged generation can be prepared with an explicit subset label, but cannot satisfy the complete roster gate. The original assets, historical receipts, failed exports and old products remain preserved. Native art inspection, full-App lifecycle/offline checks and multiplayer endurance remain separate acceptance work after assembly.
