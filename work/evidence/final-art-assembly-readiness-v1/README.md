## Concrete assembly findings

1. **No normalization application exists in overlay-v3.** It copies original handoff masks, then generates the pack. Applying normalized images before handoff replacement would overwrite the correction. The reviewed current53 receipt has 212 masks, including 106 runtime @2x masks; every original mask descriptor and all 53 handoff identities still match catalog56. The three later IR fighter/gunship/ISR handoffs are outside that receipt. Apply only explicitly reviewed, identity-matched derivatives after all handoff replacements and before final pack generation. A private guarded successor is now separately authorized; this report does not claim it exists or passed yet.

2. **Props must not be forced through the catalog UI contract.** overlay-v3 accepts `prop.*`, but lines 45–48, 73 and 90 universally demand UI-check evidence/eight images and advertise portrait/build keys. All 26 actual inherited props have no indexed UI. This is a future new-prop-handoff limitation, not a present assembly blocker: keep their verified base files unchanged, as the overlay already requires. Do not infer UI absence from `role_id: null` alone—building IDs also use null and do have authored UI. No adapter relaxation or fabricated exports is warranted now.

3. **Replacement precedence is explicit and sound for the selected roster.** overlay-v3 rejects duplicate IDs/roles and ambiguous source hashes. It removes the selected sprite directory in a new clone before copying the exact closed sidecar/atlas graph, so old pages cannot survive for that ID. UI replacement is by exact destination. There is no automatic newest-wins rule: freeze one accepted handoff per ID, preserving historical corrected/failed versions outside the union. A future role-key migration would need explicit removal of obsolete UI keys/files; none is required by the inspected current53→56 append.

4. **Use a fresh current-client base.** Catalog references intentionally use v25 for historical inventory only. The final base must pin the then-accepted client, Go/WASM/worker/host, UI, terrain, FX and content together. Recheck the 48 inherited IDs against the lineage receipt on that base, rather than assuming any current base carries the same files. Current queue completion does not qualify an old v25 executable.

5. **Content identity must be regenerated after the last byte change.** The frozen packaging-v3 `art-plugin.mjs` is currently byte-identical to the live helper. `writeBasePack` canonicalizes only the generated content-index version field, hashes all packaged files, derives `content-v1-<hash>`, then publishes the matching index/manifest. A same-path mask replacement can leave art-index bytes unchanged but must change the pack/content generation. Do not manually retain the previous pack version, patch an old product, or copy an old manifest after normalization. The runtime binds exact content-index bytes, manifest identity and every file descriptor.

6. **No budget change is justified.** The latest exact ISR closure reduces the all-eight-UI projected upper bound to 15,005 files, 995 below the unchanged 16,000 cap. The production art plugin selects four @2x UI files per role; the handoff overlay currently copies all eight accepted derivatives. Both world qualities remain required. No need now to add filtering, delete @1x source images or raise limits. The final actual assembled file count, per-file/manifest limits and 2 GiB encoded total are still unproven; the projection retains old fixed-pack assumptions.

7. **Ordinary `make build` does not consume private handoffs.** `Makefile:4` invokes `scripts/local.mjs`; `buildPackage` at line 90 invokes normal runtime and Vite builds, and `client/vite.config.ts:16` points the art plugin at repository `assets`. The plugin derives its index from `assets/build`, selects runtime dependencies, and emits a new pack. Private overlay outputs are not an input. Thus final acceptance of a private product alone would not make the documented command reproduce that art. The current `cfc8554` local script, including its player-guide copy, is pinned in the supplemental facts.

8. **Freeze selected art while ordinary packaging runs.** `buildSourceIdentity` in `scripts/package-integrity.mjs:81` covers Go/proto/content JSON and go.mod/sum, not client or art. A self-consistent pack hash cannot prove the bytes still equal reviewed handoffs if authoring changes files during sequential Vite copying. A selected-asset before/after inventory and comparison to packaged descriptors is required for final assembly; no broader renderer or gameplay change is implied.

The minimal proposed integration is a separately reviewed, receipt-bound publication of the final selected world/UI exports into the existing `assets/build` tree, with old exports backed up and immutable handoff originals retained. Apply reviewed team-mask derivatives last in that published generation. Keep inherited props exact and do not modify models or regenerate images. Then run the ordinary documented `make build` under a source/art freeze and verify the packaged dependency graph against the published receipt. The existing plugin naturally selects only runtime @2x UI dependencies, so its resulting graph will differ from the private all-eight-UI overlay; record the actual new identity rather than reusing an overlay hash. If publication is not desired, an explicit reviewed manifest-driven build input is an alternative, but it requires more production plumbing. Neither path is implemented or authorized for asset publication by this audit.
