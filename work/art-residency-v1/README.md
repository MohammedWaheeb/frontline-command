# Sprite residency under memory pressure

Private correction of recent offscreen atlas retention. The actual frozen ArtLibrary keeps all six synthetic 64 MiB pages (384 MiB) after a current frame uses only two: its ten-second rule excludes every recently used page. The private candidate reclaims the three least recently used inactive pages, retaining both current-frame pages and the newest cached page at 192 MiB. The same real Pixi TextureSource/Texture/SpriteSheet methods run in both probes. Dimensions are synthetic; no large RGBA backing, GPU or browser allocation is measured.

`candidate-art.ts` adds `trim(frameStartedAt?: number)`. A complete-frame caller can reclaim only pages last requested before that paint started. It sorts globally across loaded sheets and stops at the existing 192/384 MiB soft targets. Pending pages cannot be reclaimed; stale candidate callbacks recheck page use before disposal. Current displayed frames remain protected even when their working set exceeds the target. Invalid/future boundaries throw before resource mutation. No-argument callers keep the original ten-second behavior.

The renderer must call this **after** every world/environment/actor/shadow/placement read. Its current trim location is before `drawTactical`, which paints the placement ghost, so passing the timestamp there would be unsafe. The renderer-performance agent owns the later separate caller delta: retain the cadence, call `art.trim(now)` at the end of render after `drawTactical`/`paintMinimap`. That integration is not present here or in live source yet.

Eight focused lifetime tests pass, as do all 498 existing runtime tests and both TypeScript checks. All 247 guarded live source/support inputs remain exact. The first full-runtime harness omitted copied `scripts/ui` dependencies and failed before execution; `runtime-tests-01.log` is retained. The corrected support snapshot and second course pass without production changes. The baseline and candidate pressure JSON results are separate.

This is not a hard decoded-memory ceiling: required active pages, in-flight reads/decodes, temporary picking canvases, UI images, terrain and native backing can exceed these nominal counters.
