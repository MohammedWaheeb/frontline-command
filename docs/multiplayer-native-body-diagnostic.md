This is a separate bounded investigation of raw browser network reports. The actual v24 one-human/three-bot match won through ordinary elimination at tick 31,479 and passed its native replay audit, but its original strict course remains failed with 1,131 unclassified `net::ERR_ABORTED` reports. That run did not collect native JavaScript reader EOF or consumed-body hashes. Loaded scenes, successful advice, HTTP 200, and browser response bodies cannot supply that missing proof retroactively.

The observer adds a promise reaction, chunk-copy/hash work, and CDP callbacks; timing and raw-diagnostic frequency cannot be compared as a performance test.

The separate diagnostic host uses the exact integrated Go source lock `3d49f3c0a344c4573d003e00768994e5a97b88b0ddff3a035ccd7febf0053750`. The diagnostic binary and source receipt are in `work/multiplayer-combat/readiness-trace-build-01`; this is not a retroactive claim about the earlier production host binary.

## Exact matching and independent results

A data-integrity proof requires the native streamed default-window context, frame/document scope, full URL, method, exact serial ordinal/cardinality, and CDP RequestId. Redirected, overlapping, unproven, service-worker, truncated, wrong-hash, or missing-final-snapshot cases fail closed. GET bytes must match the immutable file; POST bytes must match the exact ordered server-written response. Server trace overflow, short writes, failures, and unmatched counts prevent proof.

Raw `loadingFailed` and Playwright failures remain in the report. An exact native EOF plus exact consumed hash can establish a complete-body fact even if the platform reported an error first. It does not establish why the platform reported it, invent application cancellation, or prove successful decoding. The report preserves whether the collector observed the failure before or after native EOF, and records actual observed cancellation separately. Unselected requests remain unproven. Native facts never turn the original long match into a strict pass.

The final report is reconciled only after browser and host close. Page errors, HTTP errors, observer faults, and unrelated console errors are strict failures. Only an explicitly requested negative control with an actual native rejection, exact unique URL, and exact corresponding network error code can account for its own console diagnostic. All original diagnostic arrays remain available.

## All-art successor (separate from the bounded four-file run)

`multiplayer-readiness-all-art.browser.mjs` preserves the frozen product, native host binary, and original six controls. It verifies every immutable art file against the existing pack receipt before launch. Every window `/art/` fetch is observed, and the report compares the full native-consumer set with exact page-target fetch identities. Non-fetch browser Image/SVG requests remain explicitly listed rather than silently counted as native JavaScript proofs.

`all-art-consumed-body-trace.mjs` uses the independently tested incremental `streaming-sha256.mjs`. Per active hash it retains a 64-byte tail, 256-byte word schedule, 32-byte state and 256-byte round constants: 608 typed-array bytes. It does not retain response chunk buffers; it consumes each original chunk synchronously before returning the same native result. Limits are 128 active hashes, 64 MiB per body, 2 GiB cumulative hashed input, and 16,384 observations. Exceeding a bound excludes proof and never cancels or changes the original response consumer. Record metadata is bounded separately; these array counts are not total JavaScript heap measurements.

Native `arrayBuffer()`/`bytes()` results can be hashed directly before the same buffer/view is delivered. Native `blob()` returns the identical immutable Blob without awaiting proof. A separate bounded asynchronous stream of that returned Blob supplies its content digest; the record identifies native method fulfillment and local Blob proof EOF separately. This is a local read of the already-returned Blob, not a second fetch or response-body read. Blob proof is limited to 8 MiB per object and 16 MiB retained objects in total. A larger or excess Blob remains unsupported. Observer scheduling and hashing overhead are explicit; this is not a performance comparison.

Native `json()`, `text()` and `formData()` expose transformed values rather than original bytes. Their calls, actual fulfilled/rejected identities and timing are recorded, but no reserialization or encoding is accepted as byte proof. Browser-loaded images and SVGs have no original JavaScript response consumer to observe. Their HTTP/CDP records remain available with this concrete limitation. No production consumer was changed to accommodate the observer.

Twenty-three focused tests passed before launch. Incremental hash vectors and chunk boundaries match Node's independent crypto implementation, including a 64 MiB multi-update course. Tests also cover original result/error identity, caller mutation, asynchronous Blob delivery, large Blob exclusion, per-body/total/active limits, cancellation, bad hashes and attribution failures. An initial unit assumption that Node's native `Response.json()` bypassed JavaScript `getReader()` was false: Undici internally uses that method. The unsupported-method identity test was corrected to test the native method boundary directly; production/browser consumption was not modified to fit that assumption.
